## 7. Technical Debt

*   **In-Memory Telemetry Metrics:** Telemetry counters (request counts, latency duration arrays) are stored in memory and reset on application restarts.
*   **Database Lock Times:** SRE checks utilize the `HEALTH_TIMEOUT` parameter (3s) to prevent lock durations. However, long-running queries run outside of lock preventions if SQL Server experiences heavy system-wide locking.

---

## 8. Remaining Risks

*   **Secret Key Strength:** The application throws boot alerts if default fallback keys are used in production mode. However, if DevOps teams fail to configure custom keys in their `.env` file, the container score drops.
*   **Connection Pool Exhaustion:** If concurrent API usage exceeds SQLAlchemy's connection pool size limits, requests might queue up. This risk is managed by database connection pool monitoring exposed in `/health/details`.

---

## 9. Recommendations

1. **Grafana Metric Exporters:** In future phases, plug in a prometheus metrics route to serialize telemetry history logs into persistent dashboards.
2. **Kubernetes Lifespan Integration:** Wire the readiness score directly to container readiness checking gates to automatically block deployments with failed setups.
