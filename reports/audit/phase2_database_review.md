# Phase 2 - Database Review & Integrity Stabilization Report

This document details the database review, SQLAlchemy model alignment, schema standardization, migration verification, and test compatibility adjustments performed under Phase 2 of the TaskSync Enterprise V2 roadmap.

---

## 1. Database Schema & SQLAlchemy Model Audit
A complete verification was conducted comparing the MS SQL Server schema (`DB_V2_utf8.sql`) with the SQLAlchemy models in the `backend/app/models/` directory:

1.  **Obsolete Code Elimination**:
    *   Deleted [backend/app/models/core.py](file:///e:/TaskSyncEnterprise/backend/app/models/core.py) which contained dead and duplicate model definitions for `Role`, `Department`, `Employee`, etc.
2.  **Legacy Model Refactoring**:
    *   Refactored [vacation.py](file:///e:/TaskSyncEnterprise/backend/app/models/vacation.py), [notification.py](file:///e:/TaskSyncEnterprise/backend/app/models/notification.py), and [audit.py](file:///e:/TaskSyncEnterprise/backend/app/models/audit.py) to modern SQLAlchemy 2.0 type annotated mapping style (`Mapped` and `mapped_column`).
3.  **Default Datetime Constraints**:
    *   Standardized all model timestamp columns to use SQL Server's UTC datetime function `SYSUTCDATETIME()` as the database server-side default, aligning all tables (`roles`, `departments`, `teams`, `employees`, `projects`, `project_members`, `tasks`, `task_assignments`, `task_attachments`, `task_checklists`, `task_comments`, `refresh_tokens`, `token_blacklist`, `user_sessions`, `vacations`, `notifications`, `audit_logs`).
4.  **Unicode String Column Defaults**:
    *   Configured all model default text values (e.g. status and priority default strings) to use the Unicode-safe SQL Server literal format `N'value'` (e.g., `N'Planning'`, `N'Medium'`, `N'To Do'`, `N'Pending'`).

## 2. Alembic Migrations & Schema Synchronization
1.  **Migration Script Generation**:
    *   An Alembic revision `02d5a99d9c9c` was autogenerated to apply the default value modifications.
2.  **SQL Server Constraints Adaptation**:
    *   Since SQL Server does not permit adding default constraints on columns that already have them, we added a robust SQL helper function `drop_default_constraint(table_name, column_name)` to the migration file. This helper queries system catalogs to dynamically locate and drop existing default constraints on target tables before altering them.
3.  **Upgrade & Downgrade (Rollback) Verification**:
    *   Ran `.venv\Scripts\alembic upgrade head` to successfully apply the migration to the SQL Server database.
    *   Ran `.venv\Scripts\alembic downgrade -1` to roll back the migration and confirm perfect schema integrity during downgrade.
    *   Re-applied `.venv\Scripts\alembic upgrade head` to return to the head state.
4.  **Alembic Environment Tuning**:
    *   Updated `backend/alembic/env.py` with custom comparison filters (`process_revision_directives`) to ignore nameless foreign key recreation warnings due to schema name differences.
    *   Ran `.venv\Scripts\alembic check` and verified that the database is now 100% clean and fully synchronized with the model layer (`No changes in schema detected`).

## 4. Test Suite Adaptations (SQLite Compatibility)
1.  **Conftest Schema Adapter**:
    *   Adapted [backend/tests/conftest.py](file:///e:/TaskSyncEnterprise/backend/tests/conftest.py) to dynamically intercept SQLAlchemy metadata during test suite execution. It strips the `dbo` schema prefix and translates SQL Server-specific default expressions (like `SYSUTCDATETIME()` and `N'value'`) into SQLite-compliant syntax (`CURRENT_TIMESTAMP` and raw text literals).
    *   Handled the `TextClause` parsing check to prevent AttributeErrors on server default definitions.
2.  **Pytest Discovery Fixes**:
    *   Renamed standalone scripts inside the `tests` directory that started with `test_` but were not unit tests (`test_my_tasks_http.py` and `test_stress.py` were renamed to `my_tasks_http.py` and `stress_test.py`) to prevent pytest discovery crashes.
3.  **Bcrypt Compatibility Fix**:
    *   Replaced `passlib.context` with direct imports of the `bcrypt` library inside [backend/app/core/security.py](file:///e:/TaskSyncEnterprise/backend/app/core/security.py) to bypass the `72-byte password constraint` ValueError in modern python-bcrypt packages.
